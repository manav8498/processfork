## What's next (top of stack — Phase 7: SDKs)

Phase 7 is **Python + TypeScript SDKs**. Current state: `pf-py` and `pf-ts`
crates exist as Phase-0 stubs that expose only `digest_of(bytes)`. We
need to flesh out the actual user-facing APIs.

Per `agent_docs/feature-spec.md` M3 + M5:

1. **Python SDK** (`crates/pf-py/`):
   - `processfork.PfStore.open(path)` → opens a store, returns handle
   - `processfork.snapshot(store, agent_id, **opts)` → returns CID string
   - `processfork.fork(store, cid, n=1, hint=None)` → returns [CID]
   - `processfork.checkout(store, cid, target_path)` → restores world
   - `processfork.merge(store, a, b, **opts)` → returns MergeReport dict
   - `processfork.diff(store, a, b)` → per-layer summary
   - `processfork.ToolProxy` wraps the effect ledger for tool intercept
   - Hand-write `crates/pf-py/python/processfork/_pf_py.pyi` so users
     get type hints
   - `pyproject.toml` for maturin build

2. **TypeScript SDK** (`crates/pf-ts/`):
   - Same surface, ergonomic Promise-returning async API
   - `package.json` with napi binary-name resolution
   - `index.d.ts` auto-generated by napi-build
   - Optional thin TS-side wrapper at `crates/pf-ts/ts/index.ts` for
     richer types (e.g. discriminated-union MergeOutcome)

3. **Tests**:
   - Python: `crates/pf-py/python/tests/test_smoke.py` boots a store,
     snapshots a fixture, merges. Run with `maturin develop` then
     `pytest`.
   - TypeScript: `crates/pf-ts/test/smoke.ts` equivalent.
   - Both gated in CI behind their respective build environments
     (already wired in `.github/workflows/ci.yml`).

Trade-off note: pyo3 0.22's `#[pyfunction]` macro under edition 2024
needs the `#![allow(unsafe_op_in_unsafe_fn)]` we already have at the
crate level. Each new function takes `Vec<u8>` rather than `&[u8]` to
dodge the same warning class (allowed via `clippy::needless_pass_by_value`
in the SKILL).
